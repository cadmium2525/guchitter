# 愚痴ったー

「過去の怒りを、後から笑える思い出にする」ための、端末内保存の愚痴日記 PWA です。React・TypeScript・Vite・Tailwind CSS・Dexie.js・IndexedDB・vite-plugin-pwa・Lucide React を使います。ユーザー登録、バックエンド、有料 API はありません。

## 実装済みの機能

- スマートフォン向けの日本語タイムライン、下部ナビゲーション、投稿画面
- タイムラインは「新しい順」「ランダム」のタブで切り替え。投稿フォームは ＋ ボタンからモーダルで開く
- テキスト投稿と複数ハッシュタグ
- 投稿フォームの ＃ ボタンから、保存済み投稿で使った全タグを使用回数の多い順に選択。新しいタグも入力できる
- 投稿の編集、確認画面を経由した削除
- 過去の投稿を引用して新しく投稿。引用元の本文・タグ・画像を表示し、元の投稿を開ける
- 投稿への返信と返信への返信。古い順に枝分かれするツリー表示、返信先からスレッドへ移動
- 1投稿4枚までの画像添付・拡大表示・編集。端末内で縮小・WebP変換し、未対応時はPNG・JPEGへ再変換
- 💢 ボタンによる怒りカウント。10 進文字列で加算し、JavaScript の安全な整数の上限で打ち切りません
- Dexie.js を使った IndexedDB 保存と再読み込み後の表示
- 本文の全文検索、複数語の AND 検索、`#タグ` の完全一致検索、タグボタンでの絞り込み
- 検索結果の新しい順・古い順・イライラ順、イライラランキング
- ライト・ダーク・端末に合わせるテーマ設定
- PWA の manifest とオフラインキャッシュ、インストール案内、下書きがある間の更新操作の保留
- ブラウザーに保存領域の保護を要求する設定。許可はブラウザーの判断に依存します
- GitHub Pages 用のビルド・公開ワークフロー
- 全投稿・タグ・画像を含む、パスワード付きの暗号化バックアップと追加復元
- ファイル共有・ダウンロード、保存確認、7日・30日・オフから選べるアプリ内のバックアップ案内

データモデル、画像の処理条件、バックアップ形式は [設計書](docs/ARCHITECTURE.md) に記載しています。iPhone Safari・Android Chromeの実機確認はまだ完了していません。

投稿モーダルを閉じても、本文・怒り値・添付画像・引用元や返信先の下書きはアプリを開いている間は保持します。保存に成功すると下書きを消し、通常投稿・引用投稿は新しい順のタイムラインへ、返信はスレッドへ移動します。ランダム順はタブを選ぶと並べ直し、イライラ値の加算や編集では順序を保ちます。ランキングの紹介バナーは表示しません。

投稿カードの「端末に保存済み」チェックと更新表示は表示しません。保存失敗時のエラー表示は維持します。タグ履歴は現在保存している投稿から集計し、同じ投稿内の同一タグは 1 回として数えます。選んだタグは本文のカーソル位置に入り、入力済みのタグは重複して追加できません。投稿の編集・削除に合わせて履歴も更新し、履歴専用の保存領域やデータ移行は追加しません。

投稿カードの本文ではハッシュタグを非表示にし、下の色付きタグだけを表示します。タグをタップすると絞り込めます。保存した原文は維持し、編集フォームでは本文とタグを確認できます。

## 引用と返信

投稿の「引用」から、過去の投稿を引用した新しい日記を書けます。引用元はカード内に表示し、タップすると元投稿のスレッドを開きます。「返信」では投稿の続きを書け、返信への返信にも対応します。吹き出しと件数のボタンで、同じスレッドをツリー表示します。引用は返信ツリーには混ざりません。

本文・タグ・画像・怒り値は投稿ごとに独立しています。引用元の表示は現在の保存内容を反映します。元投稿を削除しても引用投稿や返信は消さず、削除されたことを表示します。書きかけの内容がある状態で引用元・返信先を変更すると確認し、通常の＋ボタンではそのまま下書きを再開します。関連付けを解除して通常投稿に変えることもできます。

スレッドURLは `#thread/投稿ID` を使うため、GitHub Pagesでも再読み込みできます。投稿データは端末内にあるため、URLだけを別端末に渡しても日記は共有されません。

## 画像

投稿フォームと編集フォームの「画像を添付」から追加します。本文がなくても画像があれば投稿できます。1枚の入力は20MiB以下、4,000万画素以下、1投稿4枚までです。長辺を最大2048pxへ縮小し、WebPの品質0.82で再エンコードします。WebPを書き出せない端末ではPNG、次にJPEGを試し、1枚5MiB以下の結果だけを保存します。小さい画像は拡大しません。

変換はブラウザー内で行い、原本や位置情報などの原本メタデータを保存しません。SVGは使用できません。HEICなどは端末のデコード対応に依存し、開けないときはJPEG・PNGへの変換を案内します。複数枚の準備で失敗したときは、その選択分を途中まで追加しません。

## バックアップと復元

設定の「バックアップと復元」で、12文字以上のパスワードと確認入力から暗号化ファイルを作ります。全投稿・タグ・怒り値・画像・日時・引用や返信の関係を含みます。AES-256-GCMとPBKDF2/SHA-256（60万回、新しいソルト・nonce）を使用し、作成したファイルを再度復号・検証してから保存操作へ進みます。見た目の設定や保存確認日時はバックアップに含めません。引用・返信の追加前に作った旧形式（schema2）のファイルも読み込めます。

「共有して保存」が利用できるiPhoneでは共有メニューの「ファイルに保存」を選べます。共有未対応時はダウンロードを使います。ブラウザーは保存先のファイルの存在を保証できないため、保存先を確認してから「保存できた」を押してください。共有キャンセルや保存失敗を完了扱いにしません。

復元はファイルとパスワードを選び、「復号して内容を確認」から件数・重複・競合を確認した後に実行します。今ある日記は残し、同じID・同じ内容の投稿は追加しません。同じIDで内容が違えば、復元する側を別のIDで追加します。画像も一緒に追加し、書き込みに失敗した場合は全体を取り消します。

パスワードを忘れると復元できません。パスワードはアプリの永続領域に保存しません。処理上限はファイル256MiB・復号後180MiB・画像合計120MiBです。端末のメモリ・空き容量によっては、それ以下でも処理できない場合があります。上限を超える場合は切り捨てず失敗を表示します。

アプリを閉じている間の自動バックアップは行いません。7日・30日・オフの設定に従い、アプリを開いた際に保存を案内します。通知権限は不要です。

## 開発

Node.js 22.20 以上の 22 系、または 24.12 以上と npm を使用します。

```sh
npm install
npm run dev
```

```sh
npm run check
npm test
npm run build
npm run preview
```

`check` は型チェック、`test` は基本テスト、`build` は公開用 `dist/` の生成、`preview` はビルド結果のローカル確認です。依存関係を固定して再現するときは `npm ci` を使います。`preview` は本番用サーバーではありません。

PWA の Service Worker は公開用ビルドで確認します。最初のオンライン読み込みとキャッシュの準備が済んでからオフライン起動を確認してください。端末から HTTP の開発サーバーを開くだけでは、HTTPS を必要とする PWA 機能の確認になりません。

ブラウザー E2E テストは次のように実行します。PowerShell では、ブラウザーの配置先をインストール時とテスト時の両方で指定してください。

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/.playwright-browsers"
npx playwright install chromium webkit
npm run test:e2e
```

テストが本番ビルドと `127.0.0.1:4173` のプレビューサーバーを起動します。このポートを空けて実行してください。Playwright のブラウザー更新時は対応するバイナリを再インストールします。詳細は [Playwright 公式のブラウザー管理](https://playwright.dev/docs/browsers) を参照してください。

## 保存とプライバシー

投稿内容はこのブラウザーの IndexedDB に保存します。日記の送信先、解析サービス、外部フォント、ログイン処理は設けません。初回表示や更新時には、GitHub Pages から HTML・JavaScript・画像などのアプリ資材を取得します。ホスティング側には一般的なアクセス情報が残り得ますが、日記本文・タグ・怒りカウントを送信する設計にはしません。

**IndexedDB の中身は平文です。** 端末のロックやブラウザーのアクセス制御を使ってください。AES-GCMバックアップは出力ファイルを暗号化する機能で、端末内データの暗号化とは別です。サイトデータの削除、プライベートブラウズ、容量不足、OS・ブラウザーによる保存領域の削除などで失われる可能性があります。端末間の自動同期はありません。

IndexedDB は URL のパス単位ではなくオリジン単位で隔離されます。`https://owner.github.io/a/` と `/b/` は同じオリジンです。他の公開アプリと同居する場合、別リポジトリというだけでは日記の隔離を保証できません。日記専用の GitHub Pages オリジンを使う構成を推奨します。

## GitHub Pages

公開先リポジトリは [cadmium2525/guchitter](https://github.com/cadmium2525/guchitter) です。配備後のアプリ URL は `https://cadmium2525.github.io/guchitter/` です。

公開するのはアプリのソースと静的ビルドです。端末内の日記データやバックアップファイルをリポジトリに追加しないでください。費用 0 円の構成は GitHub Free の公開リポジトリと GitHub Pages を前提とし、独自ドメインや有料サービスは必要ありません。公開サイトを開く利用者には GitHub アカウントは不要です。

1. このプロジェクトを公開 GitHub リポジトリの `main` ブランチへ保存します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. `main` への push または Actions の手動実行で、型チェック・テスト・ビルドが通った成果物を公開します。
4. 通常のプロジェクトサイトは `https://<owner>.github.io/<repo>/` です。ワークフローはリポジトリ名から `VITE_BASE_PATH=/<repo>/` を設定します。`<owner>.github.io` というリポジトリでは `/` になります。

独自ドメインでルート配信する場合は、ワークフローのベースパス設定を `/` に変更してください。既存の日記はオリジンを変えると自動移行されません。公開済み URL や実際の GitHub Pages 配備の成功は、このファイルを作成しただけでは確認されません。

GitHub Pages の設定は [GitHub 公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、Vite の配信パスは [Vite 公式ガイド](https://vite.dev/guide/static-deploy#github-pages) を参照してください。
